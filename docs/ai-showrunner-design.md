# Design: Recut Showrunner — Autonomous AI Short-Drama Agent

Generated by /office-hours · Mode: Builder (hackathon)
Track 2: AI Showrunner — Qwen Cloud Hackathon
Supersedes: the original Recut (reel format-borrower) direction

## Problem / track alignment
The track wants an **agent that autonomously handles the entire short-drama pipeline** —
scriptwriting → storyboarding → video generation → editing — judged on **narrative
ability**, **multimodal orchestration**, and **quality under a limited token budget**
(highest token allowance of any track). The original Recut made reels from a creator's
own footage; that's the wrong product. This pivots to a true AI Showrunner.

## CEO review — locked scope (SCOPE EXPANSION, UX-focused)

**Organizing principle: one elegant flow, editing optional everywhere (no modes).**
A single linear pipeline. At each stage the agent auto-generates a proposal, and the
human **approves to advance**. Every generated artifact has inline controls that are
always available but never required:
- **Script:** edit any line, regenerate a beat, or accept as-is.
- **Cast & style:** each character/location is a generated reference image — regenerate
  with a new prompt, edit it with the image model, upload your own, or accept. Pick/lock
  the visual style.
- **Storyboard:** edit / reorder / add / remove shots, or accept.
- **Production:** regenerate any single shot or swap in an upload; otherwise the agent
  generates everything.

If the human just keeps approving, it feels fully automatic; if they tweak, they're
directing — same flow, no toggle. The approve-to-advance gate before video generation
enforces the token discipline: no Wan tokens spent on an unapproved plan.

**Accepted expansions (all map to scored dimensions):**
1. **Consistency critic** — Qwen-VL compares each generated shot's keyframe to the
   character/location reference; auto re-rolls on drift. Solves the #1 risk + is a
   visible multimodal-orchestration showpiece.
2. **Style-lock** — a locked visual style (noir / anime / claymation / storybook)
   applied to every reference + shot. Hides drift, looks intentional, differentiator.
3. **Visible writers' room** — writer + critic multi-agent loop, shown live as a
   transcript. Maps to the narrative-ability score.
4. **Quality-per-token scoreboard** — tokens, $/finished-second, re-roll count, critic
   scores vs a naive generate-everything baseline. Maps to the token-budget score.

**Two demo-risk mitigations (build in):** preflight Wan i2v first; the async stand-in
architecture means the cut plays instantly and fills in, so the live demo runs the agent
on a short slice while the full film is pre-generated.

## What makes it cool (the "whoa")
1. **Premise → watchable short film.** Type a logline; the agent writes, storyboards,
   casts, generates, and edits a coherent 30-90s drama with a real beginning/middle/end.
2. **Character & world consistency across shots** — the thing most AI-video demos fail.
   The same character looks the same in shot 1 and shot 12.
3. **Interactive pre-production, autonomous execution.** The human co-authors where taste
   matters (script, shot list, casting/consistency), then hits go and the agent takes it
   away — generating every shot and assembling the cut on its own.

## Product flow
```
 PRE-PRODUCTION (interactive, human-in-the-loop, cheap tokens)
   1. Premise        logline + tone + length  ──▶ Qwen-Max
   2. Writers' room  logline → beat sheet → scene/shot script (writer + critic loop)
                     human edits any line, regenerates beats
   3. Storyboard     each scene → ordered shots (shot type, camera, action, dialogue),
                     human reorders / edits / adds / removes shots
   4. Casting/bible  per character+location: GENERATE reference (text-to-image) OR
                     UPLOAD own image; human approves & locks the reference
        ── human clicks "Action!" ──▶
 PRODUCTION (autonomous agent, expensive tokens, async)
   5. Generate       per shot: Wan image-to-video seeded from the character/location
                     reference (consistency); pure establishing shots use text-to-video
   6. Voice          per-character dialogue/narration via CosyVoice; captions burned in
   7. Score & re-roll director-critic scores each shot; re-generates the weakest within budget
   8. Assemble       ffmpeg: concat shots, mix VO + music bed, 9:16, export MP4
```

## Architecture — keep the spine, rebuild the creative layer
**Reuse (validated live):** `core/models.py` + `qwen_clients.py` (Qwen-VL/Max, Wan t2v,
image, CosyVoice — intl endpoint working), `pipeline/render.py` (ffmpeg, ASS captions,
audio mix, concat, resumable), `core/queue.py` (Postgres jobs), `worker/`, `core/storage.py`,
`mcp/` server, `api/` app, `config.py`, the canonical-timeline render contract.

**Rebuild (new domain):**
- **Schemas:** `Production` (the film), `Character`, `Location` (show bible w/ reference
  asset_id + locked flag), `Scene`, `Shot` (shot_type, camera, action, dialogue,
  character_ids, location_id, generation prompt, source: generated|upload|standin,
  asset_id, status). The render Timeline is derived from the ordered Shots (reuses the
  existing render engine — a Shot maps to a render slot).
- **Pipeline:** `writers_room` (logline→beats→script, writer+critic), `storyboard`
  (scenes→shots), `casting` (generate/upload + lock references), `generate_shot`
  (i2v from reference | t2v), `voice` (CosyVoice per character), `score_shot`
  (director-critic), `assemble` (→ render engine).
- **Showrunner agent:** orchestrates the above as **MCP tools**; autonomous in
  production, with deterministic fallbacks (standin clip) so the demo never blanks.
- **New pre-production UI** (reuse the design system): Premise → Script → Storyboard →
  Cast → Production (live generation progress) → Export.

## Character/world consistency (the centerpiece) — HYBRID
- **Reference bible:** per character & location, a locked reference image, created by
  **text-to-image (Qwen-Image)** OR **user upload**. Human approves/locks.
- **Shots with a character** → **Wan image-to-video** seeded from that reference frame.
- **Pure establishing / b-roll** → text-to-video.
- Consistency-critic (Qwen-VL) can compare a generated shot's keyframe against the
  reference and flag drift for a re-roll.
- Risk: validate Wan **i2v** on the intl key first (preflight, like we did for t2v).
  Fallback: if i2v is weak/unavailable, degrade to t2v with the reference description +
  fixed seed.

## Token-budget discipline (scored)
- Lock the entire plan (script, shots, cast) using **cheap text + image tokens** before
  any video. The human approves, so we never spend video tokens on a rejected plan.
- Video (Wan) only on **approved shots**; per-production hard cap (reuse
  `project_token_cap`). Director-critic re-rolls only the weakest shot(s) within budget.
- **Quality-per-token scoreboard**: tokens spent, $/finished-second, re-roll count,
  critic score — the headline metric.

## Approaches considered
- **A. Hybrid reference-bible + i2v (CHOSEN).** Best consistency + most impressive;
  needs i2v preflight. Generate-or-upload references.
- **B. Text-only (templated prompts + fixed seeds, t2v).** Simpler/safer (t2v proven),
  but faces/outfits drift — weaker on the scored consistency dimension.
- **C. i2v for everything.** Max control, more image steps, every shot depends on i2v.

## Success criteria / demo (3 min)
Type a logline → watch the writers' room produce a beat sheet + script → tweak a line →
review the storyboard → cast 2 characters (one generated, one uploaded) and lock them →
click "Action!" → agent autonomously generates consistent shots + VO + music → exports a
coherent 30-90s drama. Close on the quality-per-token scoreboard. Second premise to show
genre range.
